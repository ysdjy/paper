## 0. 接入方式（不修改测试模块）

状态机用 **外部控制器** 方式接入 `test_mode_ui.py`，不改动 `scene_interface` 任何文件：

- 控制器类：`state_machine.skill_test_controller:SkillTestController`
  （位于 `projects/franka_skill_state_machine/state_machine/skill_test_controller.py`）。
- 协议：`__init__(session)` → 可选 `build_window()` / `on_reset()` → 每帧 `step(session)`，
  返回 env action（`session.provider.make_joint_action_from_q_des(...)`）或 `None`（交还默认 hold）。
- 它只用 `session.env` / `session.provider`，自建 `IKJointAdapter` / `TargetRegistry` /
  `SkillExecutor(backend=joint)`。

启动（GUI，手动点 Skill Test 窗口的 Start）：
```bash
DISPLAY=:1 ~/miniconda3/envs/env_isaaclab/bin/python \
  projects/franka_v1_skill_lab/scene_interface/test_mode_ui.py \
  --device cuda:0 --no_cameras \
  --controller state_machine.skill_test_controller:SkillTestController
```
无人值守自动序列（用环境变量，自动依次跑技能并打 `[AUTORUN]` 结果，便于回归）：
```bash
SKILL_TEST_AUTORUN="open_door:microwave,close_door:microwave,open_drawer:middle_drawer,close_drawer:middle_drawer" \
DISPLAY=:1 ~/miniconda3/envs/env_isaaclab/bin/python \
  projects/franka_v1_skill_lab/scene_interface/test_mode_ui.py \
  --device cuda:0 --no_cameras \
  --controller state_machine.skill_test_controller:SkillTestController
```

## 1. 当前测试结论（2026-06-14，加载最新保存场景）

| 技能 | 结果 | 关键数据 |
|------|------|----------|
| 开抽屉 middle_drawer | ✅ 纯物理 | 拉开 0.20 m，`drawer_joint_target=None`（无驱动作弊）|
| 关抽屉 middle_drawer | ✅ 纯物理 | 回到 0.009 m |
| 开门 microwave（从全关）| ✅ 纯物理 | 拉开到 27.73°（修复把手坐标后）|
| 关门 microwave | ✅ 纯物理 | 27.73° → 1.77° |
| 连续“关后再开”门 | ⚠️ 偶发 POSITION_TIMEOUT | APPROACH 距目标 4.7cm 收不动（可达余量，见 §2.3）|
| 抓 cube_1 / 放置 | ❌ | cube 随机区在机器人身后（见 §2.2）|

**结论：技能逻辑本身正确**（抽屉开关、门开关纯物理均通过）。剩余失败都来自**场景摆放**或
**接口侧把手坐标算法**，与状态机算法无关。

## 2. 场景 / 接口侧存在的问题

### 2.1【接口 BUG，重要】门把手坐标在微波炉非 0.35 缩放时算错

- 现象：开门时机械臂精确到达技能算出的抓取点（err≈0），但夹爪闭合到 `gw=0`（抓空），门 0°。
- 实测：`microwave_door_config.MICROWAVE_SCALE=0.35`（假设均匀），但保存场景里微波炉
  `xformOp:scale=[0.30, 0.25, 0.30]`（非均匀且≠0.35）。把手坐标算法是 `link_0位姿 + offset`，
  **offset 世界度量、直接套用、不随实际 prim scale 缩放** → 仅当 scale 恰为 0.35 时才对。
- 误差量化（诊断脚本 `projects/franka_skill_state_machine/entries/debug_microwave_handle_coord.py`）：
  ```
  (A) 算出的把手点   = [0.759, -0.247, 0.397]
  (B) 真实 DoorHandleProxy = [0.761, -0.122, 0.423]
  误差 = 12.7 cm   （把手条仅 ~2.2cm 厚 → 必然抓空）
  ```
- **状态机侧已自修**：`microwave_door_skill.py` 启动时改为从真实 `DoorHandleProxy` prim 反算
  link_0 体坐标系下的真实 offset（门关时标定、缓存复用），对任意 scale/朝向都正确。修复后开门
  从抓空 → 拉开 27.73°。
- **接口侧待修（建议）**：`scene_interface` 的 `obs.handles["microwave_door"]`（`handles.py`，
  注释明确写“offset 直接套用、不乘 scale”）**用的是同一个错误公式，目前仍带 12.7cm 误差**。
  其它消费者（VLA/感知/未来直接吃 `obs.handles` 的状态机）会踩同样的坑。
  - 建议改法（二选一）：
    1. **读真实 proxy（推荐）**：`obs.handles` 直接返回 `DoorHandleProxy` / 各 drawer handle proxy
       的世界位姿（子 prim 已随 scale/位姿正确放置），与 scale 无关、与门角度无关。
    2. **按实际 prim scale 重算**：读 `/Microwave` 的 `xformOp:scale`，把 config offset 按实际
       scale/0.35 校正（注意非均匀 scale + link 轴向置换，易错，不如方案 1 稳）。

### 2.2【场景摆放】cube/knife 初始化区域在机器人身后

- 现象：`grasp cube_1` 直接 `TARGET_UNSAFE: grasp x outside workspace: x=-0.1766`。
- 实测：cube_1 在 `(-0.176, 0.518)`，`InitCorner_0` 在 `(-0.294, 0.198)`——均为**负 X**
  （机器人朝 +X，这些落在机器人身后/左侧），超出前向工作空间。
- **建议（场景修改）**：在布局编辑器把四个黄色 `InitCorner` 方块拖到机器人**正前方（+X 一侧）**、
  绿色可达环内、且避开门打开后的扫掠弧；然后 Save V1。

### 2.3【场景摆放】微波炉太远/太高，把手接近可达边缘

- 现象：连续“关后再开”门时 APPROACH `reach timeout (err=0.047)`（差 4.7cm 收不动）。
- 实测：微波炉 world `(0.90, 0, 0.44)`，把手 z≈0.42。距离/高度处于 Franka 可达边缘，IK 收敛余量小；
  全关门首开能成功，但循环复开偶发失败。
- 影响：实际任务流“开微波炉→放刀→关”只一开一关，**不受影响**；但为稳健建议优化摆放。
- **建议（场景修改）**：微波炉**门面朝机器人**、把手落进绿色可达环（更近、更低，别在 z≈0.44 远处）。
  缩放可任意（状态机已能自适应把手坐标），但**门的朝向**最好让把手朝向机器人。

### 2.4【测试环境注意】Joint Driver 面板与纯物理技能的刚度冲突（已绕过）

- `test_mode_ui.py` 启动用 `free_microwave_door=False`（门保留刚度，给手动滑块面板位置驱动），
  且 `Joint Driver` 面板**每帧**对家电关节下位置目标。这会与纯物理技能（夹爪拉门/抽屉）对抗。
- **状态机侧已绕过**：门技能运行时自己把铰链刚度置 0；抽屉由 `SkillTestController` 在技能启动时
  临时置 0（`write_joint_stiffness_to_sim`，**仅运行时内存、不保存**）。关节 stiffness=0 后，面板的
  位置目标变为空指令，不再较劲。
- **可选接口改进**：给 `SceneConfig` 增加 `free_cabinet_drawers` / `knife_blade_lock` 开关，
  让“纯物理测试”场景一键把抽屉/刀关节设为自由，免得每个消费者各自在运行时放开。
